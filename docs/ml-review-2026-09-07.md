## Findings to fix

### 1. P1 — Reject invalid sensor inputs before constructing a model window

Locations: [predict.py](../ML/SIH-2026/ml/predict.py), lines 114–129 and 353–357; [feature_engineering.py](../ML/SIH-2026/ml/feature_engineering.py), lines 26–31 and 45–52.

`push()` checks that keys exist, then calls `float()` and appends the values. It does not check finite values, sensor health, channel ranges, sequence validity or freshness. Downstream statistics turn empty/non-finite inputs into zeros, so the later finite-feature check cannot detect the lost measurements.

Controlled reproduction using the committed models:

- Every input frame had `sensor_health` set to `fault`, but inference still produced a `CRITICAL` verdict.
- Every measurement was NaN, but inference produced temperature, sensor temperature, RPM and vibration RMS all equal to `0.0`, with a `CRITICAL` verdict.
- A JSON-null vibration measurement raised `TypeError`. The stdin loop catches only `ValueError`, so this input can terminate the streaming command instead of yielding a structured acquisition error.

This matters on the actual rig: a stale Hall reading can contain numeric zero, and sensor failures must not become apparent mechanical anomalies. Reject or quarantine invalid frames, invalidate the affected window, and return an explicit data-quality state. Keep valid measured zeros distinct from missing data. Validate before statistics rather than replacing invalid measurements with zero.

### 2. P1 — Detect live gaps even when no `segment_id` is provided

Location: [predict.py](../ML/SIH-2026/ml/predict.py), lines 101–108 and 135–144.

The code resets buffers on an explicit segment change or a large backward clock jump. Live gateway frames have no cleaned-dataset segment IDs. There is no per-sensor forward-gap/sequence-reset detector. Readiness checks only frame count and the distance between the oldest and newest timestamps; it does not check gaps inside that span.

Reproduction: nine observations per sensor, at 0–3.5 seconds in 0.5-second steps and then at 9.5 seconds, produced a verdict across the **six-second internal dropout**. This exceeds the five-second transport-gap rule used to clean the training recording. These were controlled test inputs, not a new hardware measurement.

Maintain per-node timestamps and sequence state, reset/invalidate on a qualifying dropout or restart, and require fresh coverage from every sensor before resuming inference. Segment IDs must be generated by the live acquisition adapter rather than relying on an optional caller field.

### 3. P1 — Make streaming window boundaries match training

Locations: [predict.py](../ML/SIH-2026/ml/predict.py), lines 124–150; [feature_engineering.py](../ML/SIH-2026/ml/feature_engineering.py), lines 90–115.

Offline training enumerates full 10-second, half-open windows with a 2.5-second step. Streaming has no equivalent window scheduler: it scores on every accepted frame as soon as the 60% coverage threshold is reached. The configured step is not used. Its rolling cutoff also includes the current boundary, unlike the offline half-open slice.

Reproduction: after only **six seconds** of input, it emitted a verdict labelled `window_seconds: 10.0`, using 13 frames per sensor. A six-second segment produces no offline training window. Sharing the feature function therefore does not establish training/streaming parity.

Use explicit start/end boundaries and a watermark/cadence shared with offline enumeration. Compare actual features and scores emitted by `push()` against offline windows, including burst delivery, end-boundary samples and segment changes.

### 4. P1 — Declare the required XGBoost dependency

Locations: [requirements.txt](../ML/SIH-2026/requirements.txt); [train_supervised.py](../ML/SIH-2026/ml/train_supervised.py), lines 73–85.

A clean environment installed only from the supplied requirements successfully ran stages 1–5, then `python ml/run_pipeline.py` exited 1 at stage 6:

```text
ModuleNotFoundError: No module named 'xgboost'
```

`build_models()` imports XGBoost unconditionally, but the dependency is absent from the requirements. Installing the recorded XGBoost version, `3.4.1`, in the isolated review environment allowed classifier training and the remaining stages to run. Add it to the declared environment or make supervised training an explicitly optional stage with a clear dependency check. Pin a tested environment if exact reproduction of committed binary models is required; scikit-learn documents that model persistence requires a compatible dependency environment. [Model persistence documentation](https://scikit-learn.org/stable/model_persistence.html)

### 5. P2 — Make the inference self-test fail when ingestion fails

Location: [predict.py](../ML/SIH-2026/ml/predict.py), lines 249–288.

The `passed` field is computed from offline feature recomputation before the ingestion checks. Ingestion failure counts never update it. The replay checks only whether any verdict was produced for each of the first 25 windows, not whether its boundaries/features/scores agree with the offline result.

Reproduction: replacing `ConveyorMonitor.push` with a function that always returns `None` still resulted in:

```json
{
  "passed": true,
  "ingest_windows_replayed": 25,
  "ingest_windows_that_failed_to_score": 25
}
```

Make ingestion failures affect the test result and exit status. Add assertions for window boundaries, numeric features, final scores and reset behaviour. The current passing self-test is useful for the shared offline feature calculation, but does not validate the live path.

### 6. P2 — Repair and enforce the imported recording checksums

Locations: [recording SHA256SUMS](../ML/SIH-2026/data/2026-09-06T17-29-57.647Z-a70e3e55-cleaned-v1/SHA256SUMS); [preprocessing.py](../ML/SIH-2026/ml/preprocessing.py), lines 42–55.

The committed `telemetry.csv` and `excluded-rows.csv` fail their shipped SHA-256 checksums. Comparison with the preserved original cleaned recording showed that the differences are **only CRLF-to-LF conversion**, not changed sensor values. `telemetry.frames.jsonl`, the manifest and segment file match the local originals byte for byte.

Preserve a declared canonical representation with Git attributes, record the conversion if retaining LF, and issue checksums for the bytes actually shipped. Check integrity before preprocessing. Do not merely claim an intact checksum chain because a `SHA256SUMS` file exists.

### 7. P2 — Do not call the fitted-baseline alert fraction a measured false-alarm rate

Locations: [evaluate_synthetic.py](../ML/SIH-2026/ml/evaluate_synthetic.py), lines 173–177; [health_score.py](../ML/SIH-2026/ml/health_score.py), lines 96–106; [synthetic_faults.py](../ML/SIH-2026/ml/synthetic_faults.py), where original windows are assigned `NORMAL`.

The report calls 10.2% a false-alarm rate on attested-normal data. These are the same 225 unlabelled windows used to fit the detector and select its approximately 90th-percentile WATCH threshold. The source manifest does not attest verified normal mechanical condition; the operator confirmed the belt was running.

The supported description is **10.2% in-fit baseline threshold exceedance**, largely expected from the quantile choice. A false-alarm estimate requires independently labelled normal evaluation data. Preserve the report's existing caveats about synthetic fault labels and avoid elevating this baseline fraction into field performance.

## Additional evaluation and integration limitations

- Feature pruning and `RobustScaler.fit()` happen on the complete baseline before segment-grouped diagnostics. The synthetic classifier also inherits that globally selected feature list. For an independent validation estimate, learn data-dependent preprocessing within each training fold. Per-feature affine scaling is largely immaterial to Isolation Forest splits, so this is not a claim that scaling alone caused the observed scores; held-out data still participates in feature selection. [scikit-learn guidance on preprocessing and feature-selection leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)
- Segment-grouped diagnostics from one recording do not establish performance on another day, load, mounting or conveyor. The documentation correctly acknowledges much of this limitation. Keep the entire source session together in future train/evaluation splits.
- The ML addition is not connected to the gateway, web dashboard or mobile app. A direct real gateway payload is rejected because it carries `ts`, while `push()` requires `ts_ms`. Integration needs an explicit timestamp/schema adapter plus the validity and segmentation handling above.
- The synthetic classifier does not demonstrate real slip, damage or rupture prediction. The committed macro-F1 values measure recovery of simulated perturbation recipes. The main anomaly score is an unusualness measure, not failure probability or remaining useful life.
