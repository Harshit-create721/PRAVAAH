# ML fixes and verification — September 7, 2026

The baseline is **real sensor data recorded from the running conveyor**. The imported
recording contains 6,527 measurements from the vibration/acceleration, thermal and Hall
nodes. Its `unlabelled` label does not attest mechanical health. Only the additional
fault examples and their labels were generated by the ML code.

This follow-up implements the corrections in [the original review](ml-review-2026-09-07.md)
of commit `203f2fe`. Existing sensor, recording and mobile work was preserved.

## Corrections

| Issue | Change |
|---|---|
| Invalid readings became model inputs or zeros | Shared validation rejects missing, null, non-finite, nonnumeric and out-of-range measurements; requires healthy sensor state; rejects reported quality issues and insufficient acquired vibration samples. Invalid input clears the synchronized window and yields data unavailable. Valid measured zeros remain valid. |
| Disconnections could be scored without segment IDs | Per-sensor timestamps and sequences detect forward gaps over five seconds, resets and reversed clocks. Windows restart after interruption. Duplicate sequence numbers are not counted twice; distinct frames sharing a USB burst timestamp remain distinct. |
| Six seconds of live input was labelled a ten-second window | Explicit half-open `[start_ms, end_ms)` ten-second windows use a 2.5-second step and close only when all required sensors reach the boundary. Finite-recording flushes cannot extend into unobserved time. |
| Self-test passed when ingestion failed | Every real frame now goes through `push()`. The test compares all emitted window boundaries, frame counts, features, scores and statuses with training. Missing, extra and mismatched windows fail. Regression tests deliberately replace `push()` with a function that emits nothing. |
| Missing XGBoost/environment dependency | Requirements now include XGBoost 3.4.1 and pin the tested package versions. A persistent local `.venv` was installed for gateway inference. |
| Imported recording checksums failed | Restored the original CRLF bytes of the two CSVs, without changing sensor values. `.gitattributes` prevents newline normalization. All nine listed checksums are verified before importing data. Explicit missing dataset paths fail instead of silently selecting another recording. |
| Evaluation used held-out data during preprocessing | The parameter sweep and grouped/chronological diagnostics fit pruning and scaling only on their training partitions. Classifier folds also fit their feature selection and class weights independently. |
| The fitted-baseline alert fraction was called a false-alarm rate | Reports and plots now call it in-fit baseline threshold exceedance. The `NORMAL` injection recipe denotes unchanged recorded baseline input, not verified health. Unsupported claims about real deployment class proportions were removed. |
| The model was disconnected from real gateway frames | The predictor accepts bridge `ts`, exported `ts_ms` and recorder payload envelopes. A gateway-owned Python worker receives individual raw MQTT frames, including health and diagnostics, and exposes a separate `conveyors[].ml` result in HTTP/WebSocket/relay snapshots. |

The worker waits for model readiness before accepting telemetry, bounds its I/O buffers,
restarts after worker failure, and invalidates on explicit node disconnect notifications.
Both Python and the gateway check freshness during silence. A missing model environment
does not take measured channels offline. The web dashboard and mobile app remove expired
scores independently when the gateway connection or model window becomes stale.

Only the unsupervised baseline ensemble runs in the gateway. Its result does not overwrite
sensor measurements, rule alarms or rule-layer risk. The generated-fault classifier is
not deployed as a damage diagnosis. The ML card describes deviation from recorded operation,
not failure probability, remaining life, or a measured percentage of belt health.

The worker integration test replays real captured payloads at their recorded cadence with
an explicit test timestamp offset, directly into an isolated Python worker. It verifies
that a model result is emitted and that a null temperature clears it. This test does not
publish to MQTT, the live dashboard, sensor history, or any training recording.

The models, feature contract, reports, CSV outputs and plots were regenerated by the
pipeline. Fold-local parameter selection now chooses 600 trees with `max_samples="auto"`.
The regenerated thresholds are WATCH 33.9, WARNING 62.2 and CRITICAL 93.7. They remain
prototype quantile thresholds fitted to one recording. Simulated-label macro-F1 is 0.963
for Random Forest and 0.968 for XGBoost; these are recipe-recovery results, not measured
fault-prediction performance. See the [generated evaluation](../ML/SIH-2026/outputs/evaluation_report.md)
and [sensitivity report](../ML/SIH-2026/outputs/synthetic_fault_report.md).

Evidence logs and the dashboard screenshot are under the ignored directory
`data/recordings/ml-review-203f2fe-20260907/`, with `fixed-` prefixes. The original review
evidence remains in that directory as well.

## Runtime and use

The updated local gateway is running on `http://localhost:8811`, connected to the existing
relay. At verification time it received **no current readings from any of the three nodes**;
all were offline and the ML result correctly contained null scores. This does not constitute
a new live hardware validation. When valid telemetry resumes, the worker requires a full
synchronized window before showing a condition score. No new training recording was started.

For subsequent launches, the gateway automatically discovers `ML/SIH-2026/.venv`. Use
`PRAVAAH_ML_PYTHON` to select a different compatible interpreter. See the
[ML README](../ML/SIH-2026/README.md) for setup, accepted inputs, watchdog behavior and
the separation between real baseline measurements and generated fault labels.

The source change includes the mobile app, live ML integration, regenerated model
artifacts, sensor reconnection fixes and recording cleanup tooling. Local APKs,
virtual environments, recording archives, credentials and assistant preferences
are excluded from the Git change.
